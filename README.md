# 🏋️ Gym Management System

Полнофункциональная система управления спортивным залом. Предназначена для учета клиентов, управления абонементами, регистрации посещений и разграничения прав доступа персонала.

## 🛠 Стек технологий

| Уровень | Технологии |
| :--- | :--- |
| **Backend** | ASP.NET Core (.NET 10), EF Core, PostgreSQL, FluentValidation, JWT, BCrypt |
| **Frontend** | React 18, TypeScript, Vite, Ant Design, Tailwind CSS |
| **Тестирование** | xUnit, Moq, FluentValidation.TestHelper |
| **Инфраструктура** | Docker, Docker Compose |

## 🧠 Принципы бизнес-логики и архитектуры

При разработке системы соблюдались следующие архитектурные и бизнес-правила:

1. **Разделение ответственности (SoC):** Контроллеры отвечают только за HTTP-маршрутизацию. Вся бизнес-логика инкапсулирована в слоях `Services`. Валидация входных данных вынесена в отдельные классы `FluentValidation`.
2. **Мягкое удаление (Soft Delete):** Сущности `Client`, `Employee`, `SystemUser` не удаляются физически. Используется флаг `is_active` / `is_deleted` для сохранения истории и целостности связанных записей (например, посещений).
3. **Гибкая модель пользователей:** Сущность `SystemUser` (учетная запись для входа) и `Employee` (физическое лицо) разделены. `employee_id` в `SystemUser` является опциональным. Это позволяет создавать обезличенные учетные записи (например, общий логин для ресепшена), не привязанные к конкретному сотруднику.
4. **Жизненный цикл абонементов:** 
   - При создании нового абонемента система автоматически рассчитывает `end_date` на основе типа (`single`: +30 дней, `month`: +30 дней, `year`: +365 дней).
   - При покупке нового абонемента предыдущий активный абонемент клиента автоматически переводится в статус `completed`.
5. **Целостность данных:** Уникальность телефонных номеров контролируется на уровне БД и дублируется валидацией DTO.

## 📂 Структура проекта

Проект имеет четкое модульное разделение по доменным сущностям (Clients, Memberships, Visits, Employees, Users, Auth).

```text
├── GymApp.Api/                  # Backend (Clean Architecture principles)
│   ├── Controllers/             # Маршрутизация и HTTP-ответы
│   ├── Services/                # Бизнес-логика и интерфейсы (I*Service)
│   ├── DTOs/                    # Контракты данных для API
│   ├── Validators/              # Правила валидации FluentValidation
│   ├── Models/                  # EF Core сущности
│   ├── Data/                    # GymDbContext и конфигурации
│   └── Middleware/              # Глобальная обработка исключений
├── gym-app-frontend/            # Frontend (SPA)
│   ├── src/api/                 # Axios-клиенты и перехватчики
│   ├── src/components/          # Переиспользуемые UI-компоненты и модалки
│   ├── src/hooks/               # Кастомные хуки для работы с состоянием
│   ├── src/pages/               # Страницы приложения
│   └── src/types/               # Глобальные TypeScript интерфейсы
├── db_sql_scripts/              # Скрипты для инициализации и наполнения БД
├── docker-compose.yml           # Конфигурация контейнера PostgreSQL
└── GymApp.Tests/                # Unit-тесты (xUnit)
```

## 🚀 Быстрый запуск (Local Development)

Для развертывания окружения не требуется ручная установка PostgreSQL. База данных поднимается через Docker.

### Шаг 1: Запуск базы данных
Убедитесь, что Docker Desktop запущен. В корне проекта выполните:
```bash
docker compose up -d
```
*База данных будет доступна на `localhost:5432`.*

### Шаг 2: Учетные данные БД
Логин и пароль для подключения к СУБД находятся в файле:  
📄 `db_sql_scripts/gym_app_user.txt`

### Шаг 3: Применение миграций и наполнение данными
Перейдите в папку API и примените миграции для создания структуры таблиц:
```bash
cd GymApp.Api
dotnet ef database update
```

Для наполнения базы демонстрационными данными (клиенты, абонементы разных статусов, посещения) выполните скрипт:
```bash
# Для Windows (PowerShell):
psql -U gym_app_user -d gym_db -f ../db_sql_scripts/seed_data.sql
# Или выполните содержимое seed_data.sql через любой SQL-клиент (DBeaver, pgAdmin)
```

### Шаг 4: Запуск Backend
```bash
dotnet run
```
*API будет доступен по адресу: `http://localhost:5144`*

### Шаг 5: Запуск Frontend
Откройте новый терминал:
```bash
cd gym-app-frontend
npm install
npm run dev
```
*Интерфейс будет доступен по адресу: `http://localhost:5173`*

## 🔑 Тестовые учетные записи

Для демонстрации RBAC (Role-Based Access Control) в системе предустановлены два пользователя (пароль для обоих: `123456`).

| Логин | Роль | Описание | Доступ |
| :--- | :--- | :--- | :--- |
| **`admin_linked`** | `admin` | Привязан к сотруднику "Петров П.П." | Полный доступ, включая управление пользователями и сотрудниками. |
| **`operator_anon`** | `operator` | Обезличенная запись (без привязки к сотруднику) | Работа с клиентами, абонементами и регистрацией посещений. Доступ к управлению пользователями запрещен (403). |

## 🧪 Тестирование

### Unit-тесты
Проект включает покрытие бизнес-правил валидации с помощью `xUnit` и `FluentValidation.TestHelper`. Тесты изолированы и не требуют подключения к БД.

**Запуск тестов:**
```bash
cd GymApp.Tests
dotnet test --verbosity normal
```

### Матрица тестирования (Use Cases)

| ID | Модуль | Сценарий (Use Case) | Ожидаемый результат |
| :--- | :--- | :--- | :--- |
| **UC-01** | Auth | Вход с валидными/невалидными данными | Возврат JWT-токена или HTTP 401. |
| **UC-02** | Auth | Попытка доступа оператора к `/api/users` | Возврат HTTP 403 Forbidden (Policy-based authorization). |
| **UC-03** | Clients | Создание клиента с занятым телефоном | Возврат HTTP 400 с сообщением об ошибке валидации. |
| **UC-04** | Clients | Удаление клиента | Статус `is_deleted` меняется на `true`, запись исчезает из общих списков, но сохраняется в БД. |
| **UC-05** | Memberships | Покупка нового абонемента активным клиентом | Новый абонемент создан, предыдущий активный абонемент переведен в статус `completed`. |
| **UC-06** | Visits | Регистрация посещения по истекшему абонементу | Возврат HTTP 400. Посещение не регистрируется. |
| **UC-07** | Frontend | Адаптивность таблиц на мобильных устройствах | Таблицы имеют горизонтальный скролл (`scroll={{ x: 'max-content' }}`), интерфейс не ломается. |

## 🗄️ Описание SQL-скриптов (`db_sql_scripts/`)

| Файл | Назначение |
| :--- | :--- |
| `gym_app_user.txt` | Содержит логин и пароль пользователя СУБД для локальной разработки. |
| `db_structure.sql` | Полный DDL-скрипт создания таблиц, индексов и ограничений (альтернатива миграциям EF Core). |
| `seed_data.sql` | **Основной скрипт для демо.** Создает 4 сотрудников, 7 клиентов (с разными статусами: active, inactive, blacklist, deleted), 6 абонементов (active, completed, expired, cancelled) и 4 посещения с разными тренерами. |
| `users.sql` | Вспомогательный скрипт для проверки хешей паролей и связей пользователей. |
